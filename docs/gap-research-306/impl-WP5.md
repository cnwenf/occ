## Merge-safety verification (the prompt's open question)

**Finding: OCC's settings merge does NOT drop a project-tier `true`.** It is a
plain lodash deep merge (`settingsMergeCustomizer` only dedupes arrays) applied
in ascending priority order user → project → local → flag → policy, so
`.claude/settings.json` setting `sandbox.allowNestedUserNamespaces: true`
survives into the merged settings and even overrides a user-tier `false`. The
`policyLocks` `restrictive: false` entry governs only the managed-settings
fail-closed **parse** (invalid-value substitution); it does no merge-time tier
filtering.

**Deviation (justified):** a plain merged read — the way OCC passes e.g.
`enableWeakerNestedSandbox` — would therefore let a project opt itself into
nested user namespaces, exactly what the official describe forbids ("true from
project settings … is ignored"). The adapter instead implements the official
`Mp` semantics (merged `false` wins outright — "false there still applies";
otherwise first DEFINED value across policy → flag → user). Reasoning is
documented in a code comment above `falseStickyTrustedSandboxBoolean`.

**Not ported (documented in code):** the official's `Pu()&&c8()` force-false leg
(subprocess env-scrub mode with the scrub-sandbox latch set) — OCC ships no
scrub-sandbox latch, so there is nothing to gate on.

## Parity limitation (required note)

Full default-block parity under the **seccomp-helper path** needs the newer
native `apply-seccomp` binary, which sandbox-runtime 0.0.44 does not ship
(0.0.44's helper only blocks `socket(AF_UNIX)` and ignores
`SRT_ALLOW_NESTED_USERNS`). The JS backport therefore gives real enforcement
parity via the **`--disable-userns` (bwrap ≥ 0.8, non-setuid) path only**; the
env prefix on the helper path is forward-compat parity (it takes effect the
moment a newer helper binary lands, exactly as the official contract intends).
`--unsetenv SRT_ALLOW_NESTED_USERNS` is unconditional in both paths, so a
host-env `SRT_ALLOW_NESTED_USERNS=1` can never smuggle the flag into the
sandbox — matching the official.

Skipped consumers with no OCC surface (research plan item A5): device-tools
`hxr` gate, eval-shell, Bash per-command sandbox-config deny, git-credential
wrap — OCC has no corresponding call sites.
